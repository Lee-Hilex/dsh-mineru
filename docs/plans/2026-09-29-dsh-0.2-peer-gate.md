# DSH 0.2.0 peer-compatibility gate audit (dsh-mineru)

- 日期：2026-09-29
- 走廊：DSH `0.1.5-rc.x` / `0.1.7-rc.x` → `0.2.0-rc.1`
- 触发：`dsh-desktop-next` 2.0.16-next（内置 `@deepseek-ai/dsh` `0.2.0-rc.1`）+ `dsh-mineru` 0.1.13
- 结论：**命中破坏性变更，已改 peer 声明**。运行时零改动；原声明让宿主整行禁用插件。

## 现象

宿主日志：

```
dsh: disabling profile plugin row "mineru": Plugin dsh-mineru@0.1.13 is
incompatible with dsh 0.2.0-rc.1: peerDependencies
{"@deepseek-ai/dsh-tools":"^0.1.5-rc.1","@deepseek-ai/dsh-settings":"^0.1.5-rc.1",...}.
Running it may cause crashes or data loss.
```

插件行被禁用后，`mineru_*` 工具、`mineru-tools` skill、`/plugin/mineru` 路由
全部不存在 —— 症状与 0.1.13 修掉的 `ctx.settings.register` 事故完全一样
（见 `docs/plans/2026-09-25-dsh-2.x-settings-migration.md`），但根因不同：
这次不是 `apply()` 抛错，而是宿主**根本没去 import**。

## 根因

DSH ≥0.2.0 在装载前对每个 profile 行做 peer 兼容性预检
（`@deepseek-ai/dsh-app-boot` 的 `evaluatePluginCompatibility()`）：

1. 只检查名字恰好是 `@deepseek-ai/dsh` 或以 `@deepseek-ai/dsh-` 开头的 peer；
   `@deepseek-ai/cordis`、`@deepseek-ai/schemastery` **不参与**判定。
2. 判定用 `semver.satisfies(runtimeVersion, range, { includePrerelease: true })`，
   运行时版本取自同目录 `dsh-app-boot/package.json` 的 `version`。
3. 任一条不满足 → 该行直接 `disabled: true`（**不是**警告）。

六个 `@deepseek-ai/dsh-*` peer 当时都是 `^0.1.5-rc.1`，其语义上界是 `<0.2.0`，
于是 0.2.0 线全部落在范围外。

0.1.13 的运行时实现（设置接缝 feature detection、`settingsNamespace(ctx)`、
client bundle 注册）在 0.2.0 上都是有效的：把 peer 范围改对之后，同一份
`lib/` 在 0.1.7 线与 0.2.0 线上都能正常激活（本机实测：宿主热重载后
`mineru-tools` skill 立刻出现在技能目录里）。

## 新契约

peer 窗口必须显式覆盖两条线：`>=0.1.7-rc.1 <0.3.0`。

- **下界 `0.1.7-rc.1`**：0.1.7 起设置接缝已经是 `Config` 派生（`ctx.settings.register`
  已移除），legacy scope 分支只作为 0.1.5 的兜底存在，不再计入声明窗口。
- **上界 `<0.3.0`**：覆盖整条 0.2.0 线（含后续 0.2.x）；0.3.0 需要重新评估。

注意 `^0.1.x` 这类 caret 写法在这一场景下不可用 —— 它们的上界永远是 `<0.2.0`。

## 本次改动

| 文件 | 改动 |
|---|---|
| `package.json`、`package-lock.json` | 六个 `@deepseek-ai/dsh-*` peer：`^0.1.5-rc.1` → `>=0.1.7-rc.1 <0.3.0` |
| `CHANGELOG.md` | `[Unreleased] → Changed` 记录 |
| `README.md`、`README.zh.md` | 安装前置条件改为「`0.1.7` 及以上，含 `0.2.0` 线」 |
| `AGENTS.md` | Peers 约定与 Known traps 同步 |
| `RELEASE.md` | 打包产物校验清单同步 |

## 复现

直接用宿主自己的判定函数，比读日志更早发现：

```js
import { readFileSync } from 'node:fs';
const { evaluatePluginCompatibility, getDshRuntimeVersion } =
  await import('<dsh-install>/node_modules/@deepseek-ai/dsh-app-boot/lib/index.js');
const manifest = JSON.parse(readFileSync('package.json', 'utf8'));
console.log(evaluatePluginCompatibility(manifest, {}, getDshRuntimeVersion()));
// undefined  → 通过
// { peers: {...}, version, runtimeVersion, exempted } → 该行会被禁用
```

本次只改声明与文档，`lib/` 未改动。
