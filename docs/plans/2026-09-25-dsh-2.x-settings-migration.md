# DSH 2.x settings migration audit (dsh-mineru)

- 日期：2026-09-25
- 走廊：DSH `0.1.5-rc.x`（`ctx.settings.register` 存在）→ `2.0.x`（`SettingsForms`）
- 触发：`dsh-desktop-next` 2.0.14-next + `dsh-mineru` 0.1.12
- 结论：**命中破坏性变更，已改源码**。原实现让插件整体不激活。

## 现象

宿主日志：

```
[warn] dsh: warning: 1 entry did not activate
[info] mineru (dsh-mineru): TypeError: ctx.settings.register is not a function
    at new apply (.../dsh-mineru/lib/index.js:35:30)
```

设置卡片报：

```
Failed to execute 'json' on 'Response': Unexpected end of JSON input
```

## 根因

1. `ctx.settings.register(ns, schema, opts)` 在 DSH 2.x 已被移除。`@deepseek-ai/dsh-settings`
   的 `settings` 服务现在是 `SettingsForms` 类，只有
   `configure/describe/update/replace/mutate/write/schema`。
2. 该调用是 `apply()` 的**第一条语句**且没有 `try/catch`，抛错 → 整个 entry 不激活 →
   `mineru_*` 工具、`mineru-tools` skill、`/plugin/mineru` 路由全部没有挂载。
3. 客户端那一半（`dsh.client` 声明的设置卡片）照常加载，于是请求
   `/plugin/mineru/config`；未挂载路由的响应是 `404` 且**响应体为空**
   （`@deepseek-ai/dsh-host-webserver`：`res.writeHead(404); res.end();`），
   而 `lib/client.js` 的 `/config` 分支是唯一没有 `try { res.json() } catch` 的地方，
   于是抛出 `Unexpected end of JSON input`。

## 新契约（DSH 2.x）

- 插件**导出 `Config`**，宿主据此自动生成设置页；
- 只有带 `meta.volatile` 的字段才会出现在表单里（`volatileForm()`），
  没有 volatile 字段 = 没有设置页；
- 页面以 **profile entry id** 为 key（`describe()` 的 `ns`、`update()` 的 `ns`）；
- volatile 字段在 `apply(ctx, config)` 里是 cosmokit 引用而不是值，需每次读取时解包。

## 本次改动

| 文件 | 改动 |
|---|---|
| `lib/config.js` | 新增 `live()` / `unwrapField()` / `plainConfig()`；`CONFIG_SCHEMA` 每个字段套 `live()` |
| `lib/index.js` | 删除 `ctx.settings.register`；`configNow()` 每次重新投影 entry config；新增 `settingsNamespace(ctx)` |
| `lib/http.js` | `deps.scope.get()` → `deps.config()`；命名空间改为 entry id；`/config` 缺页时返回 503 + hint |
| `tests/settings.spec.js` | 新增 9 条契约测试（含"调用 `register` 就报错"的回归守卫） |

## 版本兼容

`.volatile()` 只在 schemastery ≥ 3.18.4 存在；profile 可能提升安装 3.18.2
（仍满足 `^3.18.0`），此时直接调用会再抛一次
`TypeError: ...volatile is not a function`。因此 `live()` 回退到
`.extra('volatile', true)`——写入同一个 `meta.volatile` 标记，任何版本都能生成设置页；
只有"热编辑"需要新版本。
